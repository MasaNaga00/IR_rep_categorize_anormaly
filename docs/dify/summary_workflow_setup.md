# Dify ワークフロー構築手順書(要約文用)

- 作成日: 2026-11-05
- 対象: 要件定義書 `docs/20261105_requirements.md` の T-02(層2)、T-03、T-05、E-08
- 任意: このワークフローが無くても、定型文のレポート(report.md)は出る。

---

## 1. 全体構成

```
[開始ノード]  findings / report
     ↓
[LLM ノード]  SYSTEM: summary_prompt.md
              USER:   注目点の一覧 + 定型文のレポート
     ↓
[終了ノード]  result = LLM の出力テキスト(要約文)
```

### 1.1 入力変数(開始ノード)

| 変数名 | フィールドタイプ | 必須 | 最大長 | 内容 |
|---|---|---|---|---|
| `findings` | 段落 | ✓ | 50000 | 注目点の一覧(findings.json の中身) |
| `report` | 段落 | ✓ | 50000 | 定型文のレポート(report.md の中身。要約は除いたもの) |

### 1.2 出力変数(終了ノード)

| 変数名 | 内容 |
|---|---|
| `result` | 要約文(400字程度の日本語) |

## 2. 作成手順

1. 「スタジオ」→「アプリを作成」→「ワークフロー」。名前の例: `repair-summary-global`
2. 開始ノードに 1.1 の2つの変数を追加する。
3. LLM ノード
   - Temperature: `0`、最大トークン数: 2000 程度
   - Response Format: テキスト(JSON にしない)
   - SYSTEM: ローカル作業フォルダの `prompts/summary_prompt.md` の `---` より下を貼り付ける。
   - USER: 次のように書き、`{{findings}}` と `{{report}}` を開始ノードの変数の挿入に置き換える。

```
# 注目点の一覧(JSON)
{{findings}}

# 定型文のレポート
{{report}}
```

4. 終了ノードに出力変数 `result` を追加し、LLM ノードの `text` を選ぶ。
5. 公開して API キーを発行し、`.env` に追加する(分類用とは別のキー)。

```
DIFY_API_KEY_SUMMARY=app-xxxxxxxx
```

## 3. 使い方

- 対話式の実行(`python anomaly_cli.py`)の段階7で「Dify で要約文も作りますか?」に y と答える(`.env` に `DIFY_API_KEY_SUMMARY` があるときだけ聞かれる)。
- または、解析が終わった実行フォルダに対して:

```
python anomaly_cli.py summarize --run <実行フォルダ> --local-dir C:\work\anomaly_local
```

- 要約は report.md の冒頭(「前提」の前)に「要約(Dify による文章)」として入る。定型文は変わらない。
- 作り直すときは `--force` を付ける(入れてある要約を置き換える)。

## 4. 要約の確認(T-05)

- 要約文の数値が、注目点の一覧にも定型文にも無い場合は、report.md の末尾に「要約の確認」として、その数値を示す。
- 「増加」「多発」などの使わない約束の言葉があった場合も、同じ場所に示す。
- 警告があった要約は、表(tables.xlsx)で数値を確かめてから使う。警告が多い場合は、プロンプトを見直す。
