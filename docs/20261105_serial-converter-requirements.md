## 1. 目的と範囲

### 1.1 目的

修理データなどの CSV にある「製品名(機種)」と「シリアル」から、**製造年月**と**製造ロット**を求めて、列として付け足す。

- 解析側(全世界修理データの傾向解析)で、使用期間・製造ロットの解析に使う。
- **他のデータ解析でも再利用する**。そのため、特定の解析に依存しない、独立した小さなツールとする。
  - 入力の列名は設定で合わせる(SC-11)。入力のほかの列はそのまま残す(SC-31)。
  - 変換結果のファイルは、そのまま別の解析にも渡せる。

### 1.2 範囲外

- 使用期間(受付日 − 製造年月)の計算は**しない**。使用期間の扱い(上限・除外の規則)は解析ごとに違うため、各解析の側で計算する。
- 修理データの分類・集計はしない。

## 2. 動作環境

- SC-01: Windows の Python(会社PCの版、3.15)で動くこと。Python 3.13 以上で動けばよい。
- SC-02: 必須ライブラリは標準ライブラリと `pyyaml`、`openpyxl`(Excel の入出力用)とする。大きなファイルでも動くように、1行ずつ読み書きする(`pandas` は使わない)。テストは `pytest`。
- SC-03: 解析側のリポジトリとは**別のフォルダ**(例: `C:\work\serial_converter\`)に置く。他の解析からも使うため。
  - プログラムのフォルダと、変換表・設定のフォルダは分ける(SC-21)。プログラムを更新しても変換表が消えないようにするため。
- SC-04: ファイルの読み書きは文字コードを明示する。入力の CSV は UTF-8(BOM の有無どちらも可)、出力の CSV は `utf-8-sig`(Excel と Tableau で読めるようにするため)。

## 3. 使い方(コマンド)

- SC-05: 変換

```
python serial_convert.py convert --input <入力ファイル> --output <出力ファイル> [--sheet <シート名>] [--config-dir <変換表のフォルダ>] [--columns <列の対応づけ>]
```

  - 入力・出力は CSV(`.csv`)と Excel(`.xlsx`)のどちらでもよい。形式は拡張子で決める(SC-15、SC-36)。

- SC-06: 変換表の検査(変換はしない)

```
python serial_convert.py check [--config-dir <変換表のフォルダ>]
```

- SC-07: 変換表のフォルダは `--config-dir` または環境変数 `SERIAL_CONVERTER_CONFIG` で指定する。
- SC-08: 終了コード: 正常 0 / 変換表や入力に問題があって処理できない 1。変換できない行があっても、それだけでは 1 にしない(行ごとの状態で示す。SC-34)。
- SC-09: 画面には短い要約だけを出す(人が手でメモできるように)。
  - 件数(全体・`mfg_status` 別)、変換表に無い機種の上位10件、警告の件数
  - 詳しい内容は出力と同じ場所の `<出力名>_log.txt` に書く。
- SC-10: 出力先にファイルがあれば、`--force` が無い限り上書きしない。

## 4. 入力

- SC-11: 入力は CSV または Excel(SC-15)。列の対応づけは `columns.yaml`(変換表のフォルダに置く)で指定する。`--columns` で別のファイルも指定できる。

| 内部名 | 内容 | 必須 |
|---|---|---|
| `model` | 製品名(開発コード) | 必須 |
| `serial` | シリアル | 必須 |
| `reference_date` | 基準日(修理データなら受付日)。周期のある方式で、どの周期かを決めるのに使う(SC-25) | 任意 |

```yaml
# columns.yaml の例
model: 製品名
serial: シリアル
reference_date: 受付日
```

- SC-12: 入力の CSV の文字コードは UTF-8 とする(BOM の有無どちらも読める。2026-11-05 確定)。UTF-8 として読めない場合は、何行目で読めなかったかを表示して止める。
- SC-13: 基準日は `YYYY-MM-DD`、`YYYY/MM/DD`、`YYYY/M/D`(時刻付きも可)、区切りの無い8桁の `YYYYMMDD`(例: `20250717`。いつも年月日の順とみなす)、Excel の日付シリアル値を受け付ける(解析側の I-04 と同じ)。Excel の入力で、セルが日付の型になっている場合はその日付を使う。
- SC-14: 正規化
  - シリアル: 全角を半角にそろえ(Unicode NFKC)、前後の空白を除き、英字を大文字にする。
  - 製品名: 前後の空白を除く(変換表の製品名も同じようにそろえてから比べる)。
- SC-15: Excel の入力(2026-11-05 追加)
  - `.xlsx` を読む(`.xls` は対象外)。シートは `--sheet` で指定し、無ければ先頭のシート。
  - 1行目を見出しとし、2行目以降を1行ずつ読む(`openpyxl` の read_only モード)。
  - 見出しが空の列は無視する。すべてのセルが空の行は読み飛ばす(出力にも出さない。件数を記録する)。
  - **シリアルのセルが数値の型の場合**: 先頭の 0 が失われている可能性がある(例: `01234567` が `1234567` になる)。整数として文字にして変換するが、`mfg_warning` に `serial_was_number` を入れ、画面の要約にも件数を出す。小数(`1234567.0` など)は整数にしてから文字にする。

## 5. 変換表(会社PCで人が作る)

### 5.1 置き場所

- SC-21: 変換表のフォルダ(例: `C:\work\serial_converter_config\`)

| ファイル | 内容 |
|---|---|
| `columns.yaml` | 入力の列の対応づけ(SC-11) |
| `settings.yaml` | タイプ2の周期の起点など(SC-23) |
| `model_types.csv` | 機種ごとのタイプ(SC-22) |
| `prefix_ym.csv` | 頭3桁 → 製造年月の対応表(タイプ1で使う。全機種共通。SC-24) |

- 初回用に、ひな形を作るコマンド `python serial_convert.py init --config-dir <path>` を用意する。既存のファイルは上書きしない。

### 5.2 機種ごとのタイプ

- SC-22: `model_types.csv`

| 列 | 内容 |
|---|---|
| `model` | 製品名。重複不可 |
| `serial_type` | タイプ(SC-23 の表のどれか) |
| `start_ym` | タイプ3 のみ: 製造開始の月(頭2桁が 01 の月)。`YYYY-MM` |
| `note` | 任意のメモ(処理には使わない) |

- 会社にある「機種名と製造年月のタイプを分類した表」から、この形に変換して作る。

### 5.3 タイプ

- SC-23: タイプの一覧(2026-11-05 時点。今後ほかのタイプが見つかったら追加する。SC-27)

| `serial_type` | 使う桁 | 製造年月の求め方 | 周期 |
|---|---|---|---|
| `type1` | 頭3桁 | `prefix_ym.csv` で表引き | なし |
| `type2` | 頭2桁(01〜96) | 起点 +(頭2桁 − 1)か月。起点は全機種共通で `settings.yaml` の `type2_cycle_start_ym` | 96か月(01〜96 で一周) |
| `type3` | 頭2桁(01〜96) | 機種の `start_ym` +(頭2桁 − 1)か月 | 96か月(一周する機種はまれだがある) |
| `prefix2_only` | 頭2桁 | 求めない(ロットだけ分かる) | ー |
| `prefix3_only` | 頭3桁 | 求めない(ロットだけ分かる) | ー |

- 頭桁は1つ進むと1か月進む(タイプ2・3)。頭桁のみのタイプでも、頭桁の数字の順は製造の順である(ユーザ確認済み)。

### 5.4 タイプ1の対応表

- SC-24: `prefix_ym.csv`(**全機種で共通**。2026-11-05 確定)

| 列 | 内容 |
|---|---|
| `prefix` | 頭3桁(英字は大文字にそろえてから比べる) |
| `ym` | 製造年月 `YYYY-MM` |

- 同じ `prefix` が2行あればエラー。

## 6. 変換の規則

- SC-25: 周期のある方式(`type2`・`type3`)の製造年月
  - 候補 = 起点 +(頭2桁 − 1)か月 + 96か月 × k(k = 0, 1, 2, …)
  - **基準日の月以前で、基準日の月に最も近い候補**を製造年月とする。
  - 基準日が無い・読めない行は、**実行日**を基準日とし、`mfg_warning` に `no_reference_date` を入れる。
- SC-26: 製造の順(`lot_order`)
  - 製造年月が求まる行: 製造年月の通し月数(年 × 12 + 月 − 1)。
  - 頭桁のみのタイプ: 頭桁の数値(例: `37` → 37)。
- SC-27: タイプは後から追加できる作りにする。タイプごとに「シリアル・機種の情報・基準日 → 変換結果」の関数を1つ作り、一覧に登録する形にする。新しいタイプを足すときに、既存のタイプのコードを変えずに済むようにする。
- SC-28: 頭桁の検査
  - `type2`・`type3`・`prefix2_only`: 頭2桁が数字であること。`type2`・`type3` は 01〜96 であること。
  - `prefix3_only`: 頭3桁が数字であること。
  - `type1`: 頭3桁は英数字でよい(表引きのため)。
  - シリアルが必要な桁数より短い場合は `invalid`。

## 7. 出力

- SC-31: 出力は、入力のすべての列を**元の順番のまま**残し、右に次の列を付け足したものとする。行の数・順番も入力と同じ(除外しない。Excel の空行だけは SC-15 のとおり出さない)。

| 列 | 内容 |
|---|---|
| `serial_normalized` | 正規化したシリアル(SC-14) |
| `serial_type` | 使ったタイプ。機種が変換表に無ければ空 |
| `lot_code` | ロットの識別子(使った頭桁。例: `05`、`A01`) |
| `lot_order` | 製造の順(SC-26) |
| `mfg_ym` | 製造年月 `YYYY-MM`。求まらなければ空 |
| `mfg_status` | 変換の状態(SC-34) |
| `mfg_warning` | 注意(SC-35)。無ければ空。複数あれば `;` 区切り |

- SC-32: 入力に同じ名前の列(`mfg_ym` など)が既にある場合は、エラーにして止める(上書きして元の値を失わないため)。
- SC-33: 出力と同じ場所に、実行の記録 `<出力名>_meta.json` を出す: 実行日時、入力・出力のパス、変換表の各ファイルの SHA-256、`settings.yaml` の内容、件数(全体・`mfg_status` 別・`mfg_warning` 別・機種別)、ツールの版。
  - 同じ変換結果を別の解析で再利用するとき、どの変換表で作ったかを確かめるため。
- SC-34: `mfg_status` の値(解析側と共通)

| 値 | 内容 |
|---|---|
| `ok` | 製造年月まで求めた |
| `prefix_only` | 頭桁のみのタイプ。ロットだけ分かる |
| `no_serial` | シリアルが空 |
| `no_model_type` | 機種が `model_types.csv` に無い |
| `not_in_table` | タイプ1で、頭3桁が `prefix_ym.csv` に無い |
| `invalid` | 頭桁が数字でない、範囲外、桁が足りない、タイプ2の起点が未設定 など |

- SC-35: `mfg_warning` の値

| 値 | 内容 |
|---|---|
| `no_reference_date` | 基準日が無い・読めないため、実行日を基準にした(周期のある方式のみ) |
| `after_reference` | 製造年月が基準日の月より後(タイプ1で起こりうる。変換表かデータの誤りの可能性) |
| `serial_was_number` | Excel の入力で、シリアルのセルが数値の型だった(先頭の 0 が失われている可能性。SC-15) |

- SC-36: 出力の形式は出力ファイルの拡張子で決める(`.csv` / `.xlsx`)。
  - Excel の出力は1シート(シート名 `converted`)とし、`openpyxl` の write_only モードで書く。
  - Excel の出力では、シリアル・`serial_normalized`・`lot_code` を**文字列のセル**として書く(先頭の 0 を消さないため)。`lot_order` は数値のセル。
  - Excel の行数の上限(1,048,576 行)を超える場合は、エラーにして CSV での出力を案内する。
  - 解析側に渡すファイルは CSV で出力する(SC-41)。

## 8. 解析側(全世界修理データの傾向解析)との受け渡し

- SC-41: 解析側は、本ツールの出力 **CSV** を「シリアル変換結果」として読み込み、**分類が終わった後のデータに結合する**(解析側は Excel の変換結果を読まない。Excel を変換した場合も、解析側に渡すものは `.csv` で出力する)。
- SC-42: 結合のキーは **製品名 + 正規化したシリアル + 基準日(受付日)** とする。
  - 修理IDは販社によって重複するため、キーに使わない。
  - このキーにすることで、解析に使う入力 CSV をそのまま変換したファイルでも、もっと大きな修理データ(例: 1年分)をまとめて変換したファイルでも、同じように結合できる(変換結果の再利用)。
- SC-43: 解析側が読む列は `serial_normalized`、`lot_code`、`lot_order`、`mfg_ym`、`mfg_status`、`mfg_warning` と、`columns.yaml` で指定した製品名・基準日の列。列名は本書のとおりに固定する(変えると解析側で読めなくなる)。

## 9. 検査(check コマンド)

- SC-51: `check` は次を検査し、問題をすべて列挙する。問題があれば終了コード 1。
  - 必要なファイル・列があるか
  - `model_types.csv`: 製品名の重複、未定義のタイプ、タイプ3 の `start_ym` の有無と形
  - `prefix_ym.csv`: 頭桁が3文字か、`ym` の形、重複
  - `settings.yaml`: `type2_cycle_start_ym` の形
- SC-52: 次は注意として表示する(終了コードは 0)。
  - タイプ2の機種があるのに `type2_cycle_start_ym` が未設定
  - タイプ1の機種があるのに `prefix_ym.csv` が空
- SC-53: `convert` も、始める前に同じ検査を行い、問題があれば変換せずに終了する。入力の見出しに、`columns.yaml` で指定した列が無い場合も同じ。
